# FitLens

Personal AI-assisted food, activity and weight tracker. Expo (React Native + web),
Supabase, TypeScript strict. Spec lives in the owner's build brief; plan and
status in `docs/PLAN.md`, decisions in `docs/DECISIONS.md`.

## Commands (run from the repo root)

| Task | Command |
|---|---|
| Install | `npm install` |
| Dev server (web) | `npm run dev` then open http://localhost:8081 |
| Dev server (native via Expo Go) | `npm -w apps/mobile run start` |
| Typecheck everything | `npm run typecheck` |
| Lint everything | `npm run lint` |
| Unit tests (core + schemas) | `npm test` |
| SQL tests (RLS, idempotency, timezone, targets) | `npm run test:db` (needs `DATABASE_URL`) |
| E2E (Playwright, Expo web) | `npm run test:e2e` (needs a Supabase project and `E2E_*` vars) |
| Apply migrations to `DATABASE_URL` | `npm run migrate` (`-- --shim` for a plain Postgres, `-- --reset` to drop and recreate) |
| Apply migrations to the linked Supabase project | `npx supabase db push` |
| Deploy edge functions | `npx supabase functions deploy` |
| Typecheck edge functions | `npm run functions:check` (uses `~/tools/deno/deno.exe`, `DENO_BIN`, or `deno` on PATH; passes `--node-modules-dir=none` so npm specifiers come from Deno's cache) |
| Import food data | `npm run seed -- --source usda|cnf|indian|all` |
| Reminder schedule (one time, after setting the function secrets) | `SUPABASE_ACCESS_TOKEN=... SUPABASE_PROJECT_REF=... REMINDER_CRON_SECRET=... node scripts/db/setup-reminder-cron.mjs` |
| Push the Indian seed to the linked project | `SUPABASE_ACCESS_TOKEN=... SUPABASE_PROJECT_REF=... npx tsx scripts/db/push-foods-remote.ts` |
| Funnel: sign-ups, finished setup, first meal, feature use | `node scripts/funnel.mjs [--days 7]` |
| Accounts and what they logged | `node scripts/users.mjs` |
| Quality walk of every screen | `node scripts/sweep.mjs <base> <outDir> <chromium|webkit> <black|white>` |
| Reset the e2e user | `npx tsx scripts/e2e-reset.ts` |
| Error reports and function logs | `node scripts/telemetry.mjs [--hours 24] [--purge]` (needs `SUPABASE_ACCESS_TOKEN` and `SUPABASE_PROJECT_REF`) |
| Regenerate DB types | `npx supabase gen types typescript --db-url "$DATABASE_URL?sslmode=disable" --schema public > apps/mobile/src/lib/database.types.ts` |

E2E notes: `npm run test:e2e` starts the web server itself; set `E2E_NO_SERVER=1`
to reuse one already running on 8081. Specs that need a Supabase project skip
with a reason until `EXPO_PUBLIC_SUPABASE_*` and `E2E_USER_*` are set; the
photo spec also needs `E2E_VISION_CONFIGURED=1` and `e2e/fixtures/meal.jpg`.
Browsers: `npx playwright install chromium` once.

Typed routes: `.expo/types/router.d.ts` is regenerated by the running dev
server. After adding a route, start `npm run dev` once before `typecheck`.

Metro under OneDrive does not see file edits reliably. After changing code,
restart the dev server with `npx expo start --web --clear`; otherwise the
browser keeps the old bundle and e2e results lie.

## Conventions

- Pure logic goes in `packages/core` with a `*.test.ts` beside it. No I/O, no React, no Supabase there.
- Shared payload shapes go in `packages/schemas` (Zod 4). Functions and app import the same schema.
- Migrations are append-only, named `YYYYMMDDHHMMSS_name.sql`. Never edit an applied file.
- Every user table: `user_id` + RLS with four `auth.uid() = user_id` policies. Add a test in `supabase/test/rls.test.ts` for each new table.
- Nulls mean unknown. Never coerce a missing nutrient to 0 anywhere (SQL, core, UI).
- Dates: store `eaten_at`/`measured_at` (timestamptz), `local_date`, `tz`. Compute `local_date` on the client at entry time with `localDateFor()` in `packages/core`.
- Writes carry an idempotency key where duplicates are possible (meals). Buttons disable while a mutation is in flight.
- Copy: calm, neutral. No "good/bad/junk/cheat", no shaming, no compensatory exercise. Tone rules are tested in `packages/core/src/feedback/tone.test.ts`.
- Secrets only in Edge Function env. The client reads `EXPO_PUBLIC_*` only.
- Usage events go through `track(name, flags)` from `lib/telemetry.ts` (no content, only names and flags); read them with `node scripts/funnel.mjs`.
- Caught errors that are not expected conditions go through `reportError(scope, err)` from `lib/telemetry.ts`; read them with `node scripts/telemetry.mjs`.
- Photo resizing on web must never draw the full photo into a canvas (iOS Safari caps canvas pixels); see `features/photo/capture.ts`.
- Commits: conventional commits (`feat:`, `fix:`, `chore:`, `docs:`, `test:`).
- A milestone is done when typecheck, lint and tests pass, the flow works in the running app, `docs/PLAN.md` is updated and a commit exists.

## Visual system

- Monochrome only: `ui/tokens.ts` holds the black (default) and white palettes; `useTheme().preference` switches them and Profile exposes the choice. Never add a colour outside the ramp; `danger` is the one exception.
- Type is Lato (`fonts.regular/bold/black`), loaded in `app/_layout.tsx`. Use `Text` variants; `label` is the uppercase eyebrow used for section labels and button text.
- Icons come from `ui/Icon.tsx` (stroke SVG). No emoji or unicode glyphs in the UI.
- One plate per screen: `Card tone="inverse"` (or `Stat tone="inverse"`) is the loud element; everything else is a hairline-bordered surface card.
- Tabs are Home, Today, Train, Stats, Coach (`(tabs)/_layout.tsx`); Diary and Profile are routes behind Home. New screens need a `.expo/types/router.d.ts` regenerated by the dev server, or delete the stale file so typecheck matches CI.
- Trainer access is per member by code; summaries come only from `trainer_members()` (security definer). Never add a policy that lets one user read another's rows directly.
- Workouts: library and plan rules live in `packages/core/src/workouts`; completed sessions are `activity_records` with note `plan:<id>` (`features/workouts/hooks.ts`).
- Phone sign-in needs an SMS provider on the Supabase project (Twilio credentials via the Management API auth config); until then the option stays hidden.
- Every way to log food must stay one tap from Today: the three tiles and the centre tab sheet (`features/day/AddSheet.tsx`).
- User-facing strings on the everyday screens go through `useT()` from `lib/i18n.tsx` (en, hi, pa; stored as `fitlens.lang`). Add the key to all three dictionaries; a missing key falls back to English. Food names, quotes and the Coach stay English.
- Dates are picked, not typed: use `DateField` (web date input, native OS picker; `.native.tsx` split) and keep values as YYYY-MM-DD.
- Times use `TimeField`, an in-app sheet with a Set time button (the browser and OS wheels have none on phones); values stay HH:MM.
- Food search matches `foods.aliases` as well as the name; give every curated dish the names people type (`supabase/seed/indian_dishes.json`, `aliases`). Searches with no result land in `search_misses` and show on the admin page.
- Deploys keep the previous build's chunks (Actions cache in deploy.yml) and `lib/stale-build.ts` reloads once on a chunk load failure; keep both when touching the workflow or the error boundary.
- Opens tracking: `lib/visits.ts` posts to `track-visit` once per tab and once on sign-in (web only, skipped under automation); invite links carry `?s=<tag>`; the admin page Opens tab reads it. Never add food or health fields to that payload.
- Reminders are web push: `public/sw.js` is the service worker, `features/reminders/push.ts` subscribes (iPhone only from the Home Screen), `reminders` holds the time. Reminder copy lives in `packages/core/src/reminders.ts` and is tone-tested.
- Admin: `/admin` reads `admin_overview()`; access is a row in `app_admins`, added only by hand (`insert into public.app_admins (user_id) select id from auth.users where email = '<owner>'` through the Management API query endpoint). Never grant it from the client or seed an email in a migration.
- Confirm quick saves with `toast('...')` from `@/ui`; never block with an alert. Animated values are `useState(() => new Animated.Value())`, not refs, and every animation checks `reducedMotion`.
- Pushed screens start with `PageHeader` (chevron falls back to the owning tab); no trailing Back buttons. Forms sit on the background; use `Note` for asides and `Chips` for multi-select.
- Brand: `EXPO_PUBLIC_BRAND_NAME`, `EXPO_PUBLIC_BRAND_TAGLINE` and `EXPO_PUBLIC_BRAND_LOGO_URL` white-label sign-in, onboarding, setup and the app name. Default FitLens with the built-in mark; the icon files under `assets/images` and `public/icons` come from `BrandMark`'s geometry.
- Visual review: `node scripts/screens.mjs http://localhost:8081/ <outDir> [black|white]` captures every screen (walks onboarding when the e2e user is fresh; reset it with any Playwright run).

## Feature flags

Driven by config at runtime (`src/lib/config.ts`): a feature whose credential is missing renders "Not configured" with a one-line reason. Nothing is mocked at runtime.
